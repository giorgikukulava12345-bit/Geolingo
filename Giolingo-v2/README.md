
# Giolingo 2 · გაშვება და განახლება

## სწრაფი გაშვება Windows-ზე

1. ძველი Giolingo-ს ტერმინალში დააჭირე **Ctrl+C**, რომ ძველი ვერსია გაჩერდეს.
2. ამოიღე ახალი ZIP ცალკე საქაღალდეში. ZIP-ის შიგნიდან ფაილი არ გაუშვა.
3. ორჯერ დააწკაპუნე **START-GIOLINGO.cmd**. საჭიროა Node.js **22.12 ან უფრო ახალი**, სასურველია 24 LTS.
4. პირველი გაშვებისას პროგრამა ჩამოტვირთავს საჭირო პაკეტებს და გახსნის საიტს ბრაუზერში. ტერმინალი ღია დატოვე.

ხელით გასაშვებად გახსენი ტერმინალი იმ საქაღალდეში, სადაც `package.json` დევს:

```sh
npm install
npm run dev
```

გახსენი ტერმინალში მითითებული მისამართი, ჩვეულებრივ `http://localhost:5173`. **index.html პირდაპირ არ გახსნა.** ძველი სტუმრის პროგრესის მისაღებად გამოიყენე იგივე ბრაუზერი და ზუსტად იგივე მისამართი/პორტი, რომლითაც ძველ ვერსიას ხსნიდი. `localhost` და `127.0.0.1` სხვადასხვა ბრაუზერის საცავს იყენებს.

## რა დაემატა

- კალენდარი აჩვენებს მიმდინარე კვირას **ორშაბათიდან კვირამდე**; დღეს ცალკე აღნიშნავს.
- ზრდასრულებისთვის ინგლისური და რუსული: თითო ენაზე **50 თავი, 200 გაკვეთილი**. A1-ზე 52 გაკვეთილი; A2-ზე 44; B1-ზე 40; B2-სა და C1-ზე 32-32.
- **Giolingo Kids**: თითო ენაზე 4 თავი / 16 გაკვეთილი, დამოუკიდებელი XP, გულები, სერია და სიტყვები. ბავშვის ანგარიშისთვის გამოიყენება მშობლის ელფოსტა; ბავშვის დაბადების თარიღი, სახელი ან მისამართი არ მოითხოვება.
- ჯამში **432 გაკვეთილი / 4,320 სავარჯიშო**. სავარჯიშოები სხვადასხვა ფორმით იმეორებს გაკვეთილის ოთხ ავტორულ სიტყვას/ფრაზას; ეს 4,320 უნიკალურ სიტყვას არ ნიშნავს.
- გაკვეთილის პირველი ეტაპია სიტყვების/ფრაზების გაცნობა, ქართული მნიშვნელობა, მოსმენა, სურვილისამებრ ხმამაღლა გამეორება. მხოლოდ ყველა ბარათის გავლის შემდეგ იწყება ტესტი.
- მრავალვარიანტიანი პასუხები, თარგმნა, სიტყვების აწყობა, წყვილების შეერთება, გამოტოვებული ასოს/სიტყვის ჩაწერა და მოსმენილის ჩაწერა.
- **გრამატიკა** გამეორების ქვემოთ: ქართული თეორია, წესები, ინგლისურისა და რუსულის განსხვავებული ახსნა, ხმოვანი მაგალითები და თითო გაკვეთილის მაგალითები.
- **ლექსიკონი** აგროვებს სწავლის ფაზაში გავლილ მასალას. აქვს ძებნა და აუდიო.
- **შეცდომების ყულაბა** აგროვებს არასწორ პასუხებს. სწორი გამეორებით სიტყვა სიიდან იშლება.
- **დონის ტესტი**: თითო ენაზე 20 დამოუკიდებელი გრამატიკული კითხვა, A1–C1 ბლოკებით. რეკომენდებული დონე შესაბამის გაკვეთილს ხსნის. დაბალი დონეების დასრულება ყალბად არ აღინიშნება.
- მიმდინარე სასწავლო ბარათი, კითხვა, შეყვანილი პასუხი და შეცდომის უკუკავშირი ინახება. დაბრუნებისას დააჭირე **„გააგრძელე“**.

მასალა A1–C1 სირთულის პრაქტიკისთვისაა განაწილებული. აპლიკაცია არ არის სრული CEFR სერტიფიცირებული კურსი; დონის ტესტი მხოლოდ საორიენტაციო გრამატიკულ შეფასებას იძლევა. თავისუფალი წერითი ნაშრომების, აუდიოჩანაწერების ადამიანის მიერ შეფასება და საუბრის სიღრმისეული შეფასება არ შედის.

წერითი პასუხები მოწმდება გაკვეთილში ნასწავლი ფორმულირებით; რეგისტრი, ზედმეტი ჰარები, ძირითადი პუნქტუაცია და რუსული ё/е არ ზღუდავს პასუხს. თავისუფალი თარგმანის ყველა შესაძლო სინონიმი არ ამოიცნობა. რუსულის პირველ პირში ზოგი ნიმუში მამრობით ფორმას იყენებს; სასწავლო ბარათზე მოცემული ფორმა გამოიყენე.

## ელფოსტით ანგარიში და ონლაინ შენახვა

შენი თანხმობით დაკავშირებულია არსებული Supabase პროექტი **geolingo**. ZIP-ში `.env` უკვე შევსებულია პროექტის URL-ით და **საჯარო publishable გასაღებით**. პაროლი ან service-role/secret გასაღები კოდში არ არის.

1. საიტზე გახსენი **პარამეტრები → რეგისტრაცია** (ან საწყისი ეკრანის „შესვლა / რეგისტრაცია“).
2. ჩაწერე ელფოსტა და მინიმუმ 8-სიმბოლოიანი პაროლი.
3. დაადასტურე მისამართი ელფოსტაში მიღებული ბმულით. თუ წერილის შაბლონი კოდს აგზავნის, შეიყვანე კოდი საიტზე.
4. შედი ელფოსტითა და პაროლით. მდგომარეობა „✓ პროგრესი ანგარიშში შენახულია“ ადასტურებს წარმატებულ სინქრონიზაციას.
5. ძველი სტუმრის პროგრესი ანგარიშში ავტომატურად არ გადაიწერება. გადასატანად პარამეტრებში დააჭირე **„სტუმრის პროგრესის გადატანა“**. ღილაკი ანგარიშის პროგრესის ჩანაცვლებას წინასწარ შეგატყობინებს.



ახალი `public.giolingo_learning_state` ცხრილი უკვე შექმნილია. `database/schema.sql` მისი საცნობარო ასლია; იმავე პროექტში თავიდან ნუ გაუშვებ. ძველი `profiles` და `completions` ცხრილები არ შეცვლილა. მონაცემებს მხოლოდ ავტორიზებული მფლობელი კითხულობს/ცვლის (RLS). სტუმარი ამ ცხრილზე წვდომას ვერ იღებს.

მდგომარეობა ცალკე ინახება სტუმრისთვის და თითოეული ანგარიშისთვის. მოწყობილობებს შორის კონფლიქტზე გამოიყენება revision-ის შემოწმება: მეორე მოწყობილობის ახალი პროგრესი ჩუმად არ გადაიწერება. შეცდომისას ადგილობრივი ასლი რჩება; პარამეტრებში ხელახლა შენახვა ან ანგარიშის ასლის ჩატვირთვა შეგიძლია. ერთდროული ცვლილებები ავტომატურად არ ერთიანდება. ბრაუზერის დახურვამდე დაელოდე „შენახულია“ სტატუსს.

XP და პასუხების შეფასება ბრაუზერში ითვლება. ეს გამოდგება პირადი სწავლისთვის, მაგრამ კონკურსის ან საჯარო რეიტინგის დაცულ ქულებად არ გამოიყენო — ამისთვის საჭიროა სერვერული შეფასება.

## ხმა, მიკროფონი და შეხსენებები

აუდიო იყენებს ბრაუზერის Text-to-Speech-ს და მოწყობილობაზე არსებულ ინგლისურ/რუსულ ხმებს. ხმის მიუწვდომლობისას ბარათი განმარტებას აჩვენებს. მიკროფონი მხოლოდ მომხმარებლის ღილაკით ირთვება; მხარდაჭერა ბრაუზერის მიხედვით იცვლება. ამოცნობილი ტექსტის დამთხვევა გამოთქმის პროფესიული შეფასება არ არის. ხმა შეიძლება ბრაუზერის ხმის ამოცნობის სერვისს გადაეცეს; აპლიკაცია აუდიოს Supabase-ში არ ინახავს. იხილე [SpeechRecognition](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition).

შეხსენება პარამეტრებიდან ირთვება მომხმარებლის ნებართვით. არჩეული ადგილობრივი დროის შემდეგ, თუ იმ დღეს არც ერთ სივრცეში არ გისწავლია, ჩნდება ერთი Notification. **საიტის ჩანართი ღია უნდა იყოს**; დახურულ ბრაუზერში გაგზავნა ამ ვერსიაში არ შედის. ამის დასამატებლად საჭიროა Web Push, სერვის-ვორკერი და სერვერული განრიგი. იხილე [Notifications API](https://developer.mozilla.org/en-US/docs/Web/API/Notifications_API/Using_the_Notifications_API).

## შემოწმება და გამოქვეყნება

```sh
npm test
npm run build
npm run preview
```

შემოწმებულია 8 ძირითადი და 8 კომპონენტური/ანგარიშის ტესტი: მასალის სრული სტრუქტურა, ორშაბათის კალენდარი, ძველი პროგრესის მიგრაცია, Kids იზოლაცია, დონეების გახსნა, სწავლის ფაზის სავალდებულო გავლა, შეცდომის დაფიქსირება, XP-ის ერთჯერადი გაცემა, ანგარიშების იზოლაცია, შეუნახავი ცვლილების აღდგენა და მოწყობილობებს შორის კონფლიქტი. საწარმოო build გადის. Supabase-ში დროებითი, დაბრუნებადი ტრანზაქციით შემოწმდა საკუთარი ჩანაწერის ხილვადობა/განახლება და სხვისი ჩანაწერის წაკითხვის/განახლების აკრძალვა. სატესტო ანგარიშები ბაზაში არ დარჩენილა.

გამოსაქვეყნებლად `dist/` განათავსე სტატიკურ HTTPS ჰოსტინგზე და დომენი Supabase-ის Redirect URLs-ში დაამატე. ტექსტის ფონტები Google Fonts-იდან იტვირთება, ხოლო მიუწვდომლობისას სისტემური ფონტი გამოიყენება.

არსებული პროექტის უსაფრთხოების შემოწმებამ ახალი ცხრილის გარეთ გამოავლინა ადრე არსებული SECURITY DEFINER ფუნქციებისა და პაროლების გაჟონვის შემოწმების გაფრთხილებები. ამ განახლებამ ის ფუნქციები არ შეცვალა. კონტექსტისთვის: [Supabase database linter](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable), [password protection](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).

## Registration without confirmation
Choose Email + password or Username + password. Usernames accept 3–24 Unicode letters, numbers and underscores; case and surrounding spaces are normalized. The username is mapped to a deterministic SHA-256 identifier at the reserved non-deliverable users.giolingo.invalid domain for Supabase password authentication. This is not a contact email. Display metadata is never used for authorization; owner RLS uses auth.uid(). Username-only accounts cannot recover a forgotten password by email.

Deployment prerequisite: Supabase Authentication → Sign In / Providers → Email → Confirm email must be OFF. Signup must return a session immediately; the UI does not pretend registration succeeded when the server returns no session. No OTP, confirmation-link or verification-mail call exists in the application. Keep password validation, session refresh and RLS enabled. Supabase itself manages authentication internals; do not delete auth system token columns or disable ownership checks.
